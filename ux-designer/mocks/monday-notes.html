Ingress migration checklist

Status: In Progress
Owner: @drew
Related: [[post-mortem-2026-05-28]] [[node-maintenance-Q2]]

Pre-migration

  • ☑ Verify nginx ingress controller is healthy
  • ☑ Snapshot current ingress resources
  • ☐ Back up etcd

Migration Steps

  1. Create new ingress resources
  • api-gateway — migrate to new LB
  • webapp — ADD TLS cert
  • admin-panel — IP whitelist
  1. Canary deployment
kubectl set image deployment/api-gateway \
  nginx=nginx:1.26-alpine

Route 10% traffic, monitor error rate < 1%

If error rate exceeds 2%, revert DNS to previous LB and scale down new ingress controller.

Notes

Scheduling the canary for next maintenance window. Need sign-off from @alex on the rollback thresholds.
