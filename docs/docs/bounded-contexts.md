## Bounded Context 1: Entity Management

**Type:** Core Domain
**Ubiquitous Language:**

| Term | Definition |
|------|-----------|
| **Entity** | A uniquely identifiable service component managed across cloud regions |
| **Entity Schema** | The structural definition of an entity's attributes (name, region, status, metadata) |
| **Region** | The cloud provider region where the entity is deployed (e.g., us-east-1, eu-west-1) |
| **Status** | The lifecycle state of an entity: `active`, `inactive`, `deleted` |
| **Soft-Delete** | Logical deletion that preserves the record but excludes it from active queries |
| **Data Residency** | The requirement that entity data remains within its designated geographic boundary |

**Boundary:** Manages CRUD operations on entities, schema validation, pagination, and multi-cloud data residency enforcement. Does **not** concern itself with service provisioning or health monitoring.

**Integration Pattern:** Publisher to **Service Registry** via **Anti-Corruption Layer (ACL)** — publishes `EntityCreated`, `EntityUpdated`, `EntityDeleted` events. Service Registry consumes them through an ACL that translates entity concepts into service concepts.

**Owned Events:**
- `entity.EntitySchemaDefined`
- `entity.EntityCreated`
- `entity.EntityUpdated`
- `entity.EntityDeleted`
- `entityManagement.DataResidencyConstraintApplied`
- `entityManagement.PaginatedResultsReturned`

## Bounded Context 2: Service Registry

**Type:** Supporting Subdomain
**Ubiquitous Language:**

| Term | Definition |
|------|-----------|
| **Service** | A deployed instance derived from an entity, tracked in the registry |
| **Provisioning** | The initial state of a service before it becomes operational |
| **Health Status** | The operational state: `unknown`, `healthy`, `degraded`, `down` |
| **Deregistration** | The process of removing a service from active rotation when its entity is deleted |
| **ACL** | Anti-Corruption Layer that translates Entity Management events into Service Registry concepts |

**Boundary:** Manages service lifecycle — registration from entity events, health status updates, and deregistration. Does **not** manage the entities themselves.

**Integration Pattern:** Consumes from **Entity Management** via ACL (Customer-Supplier — Entity is Supplier, Service Registry is Customer). Publishes events to downstream provisioning pipelines.

**Owned Events:**
- `svcreg.ServiceProvisioningRequired`
- `svcreg.ServiceHealthUpdated`
- `svcreg.ServiceDegraded`
- `svcreg.ServiceDeregistered`

## Bounded Context 3: Infrastructure (Generic)

**Type:** Generic Subdomain
**Ubiquitous Language:**

| Term | Definition |
|------|-----------|
| **Graceful Shutdown** | The process of draining in-flight requests and completing event processing before termination |
| **Error Disposition** | The classification of error outcomes: `ack` (success), `badrequest` (non-retryable), `retry` (recoverable) |
| **DLQ** | Dead-Letter Queue — destination for messages that exceed maximum retry attempts |
| **Trace Span** | An OpenTelemetry span recording the duration and metadata of a single operation |
| **Data Residency Route** | The routing decision that determines which observability backend receives telemetry data based on the entity's region |

**Boundary:** Cross-cutting infrastructure concerns — graceful shutdown, error handling, observability, and data-residency-aware telemetry routing. Spans all other contexts.

**Integration Pattern:** Shared Kernel — all bounded contexts share the same error disposition types, trace context propagation, and shutdown coordination via `errgroup` and `signal.NotifyContext`.

**Owned Events:**
- `infra.ServiceShuttingDown`
- `infra.MessageRetryExceeded`
- `infra.RequestSpansExported`
- `infra.DataResidencyRouteApplied`
- `infra.MetricsSnapshotCollected`
